## 1. 사장님과 일하는 방식

- 사장님은 회사원이면서 개발자. 이 서비스는 지금은 혼자 쓰고, 수익이 나면 제품화한다.
- 사장님은 **폰으로 채팅에서 지시**하고, 사이트(Vercel)에서 확인한다. 회사에서도 일을 시킨다.
- 노트북은 **Ubuntu 20.04** (Claude 데스크톱 앱 없음). Claude는 클라우드 세션에서 코드를 고치고 GitHub에 push한다.
- 배포: `main` 에 push → Vercel 자동 배포. 기능 브랜치(`feat/...`) push → Vercel 미리보기.
- **작업 순서:** 기능별 브랜치 → push 전에 바꾼 내용을 짧게 요약 보고 → 미리보기 확인 → 사장님이 "머지해" 하면 `main` 에 머지.
- "구현해" 라고 하기 전에는 구현하지 않는다. 계획·설명을 먼저 요청하는 경우가 많다.
- 설명은 쉽게, 한 번에 이해되게. 사장님 말과 Claude 이해가 다르면 먼저 말한다.
- 이 클라우드 세션에서는 npm 설치가 안 된다 (네트워크 제한). 문법 검사·순수 로직 테스트만 하고, 빌드 확인은 Vercel 배포 결과(GitHub 커밋 상태)로 한다.

## 2. 원래 기획서 요약 (기능을 빼지 않고)

**목적:** 알바몬 등 재택·프리랜서 플랫폼의 반복 업무(데이터 수집, 타이핑, 라벨링, 문서 정리)를 AI 에이전트·웹 자동화로 처리해
'인건비와 AI 연산비의 차익'으로 수익을 낸다. 본인 노동 시간 최소화, 폰으로 경영, 가족(어머니)도 관리할 수 있는 간편 모드와 비용 안전장치.

**운영 컨셉:** 폰 안에서 키우는 내 회사. 부서 이름이 적힌 직사각형 카드. PC는 전체 조직도·채팅·재무 지표, 간편 모드는 신호등·오늘 수익/지출·재시작/긴급정지만.

| F1 | 마케팅 (일감 탐색·수주) | 알바몬 등 구인 공고 주기 수집, 자동화 가능 업무 필터, 재무팀이 지정한 적자 업무 제외, 지원서 초안·발주처 응대 보조 (자동 / CEO 승인 후 지원) |

**로드맵(원안):** 1) 시장 검증(알바몬 데이터, 수동 AI 처리 3건, 마진표) → 2) 안전장치·뼈대(SOP·RAG, 재무 게이트웨이·킬 스위치 우선) → 3) 모바일 UI·조직도·채팅 → 4) 파일럿 1개 부서 → 손익 확인 → 증설.

**리스크 대책(원안):** 토큰 폭주 → 중앙 게이트웨이 + 킬 스위치 + 반려 최대 3회. 계정 정지 → 무차별 매크로 지양, 합법적 작업 위주. 품질 미달 → 검토 부서 + CEO 최종 승인(반자동). 시장성 오판 → 개발 전 1주 시장조사.

**기획서 질문에 대한 사장님 결정:**
- 1단계 승인 방식: **반자동** (사장님이 버튼을 눌러야 최종 실행).
- 손익 계산의 플랫폼 수수료·세금 → 재무팀 구현할 때 반영.
- 알바몬 사기 공고 → AI는 **찾기만** 하고, 지원은 사장님이 직접 하면서 거른다.
- 발주처에 AI 처리 사실 고지 → 사장님이 실제 지원하면서 대화로 정한다.

## 3. 기획서에서 바뀐 결정 · 추가된 부분

- **부서 3개로 시작:** 비서 / 마케팅사업부 / 투자운영사업부(주식·비트코인). 투자운영사업부는 원래 기획서에 없던 부서.
- **마케팅사업부 범위(사장님 정의):** 인스타그램·쓰레드 자동 운영과 기획 + 다른 재택업무로 수익을 낼 수 있는 수익모델 찾기와 개발 (기획서 F1 알바몬 일감 탐색 포함).
- **비서 범위(사장님 정의):** 내 일정(구글 캘린더), API 크레딧 현황, 사용 토큰 비용·남은 크레딧 보고(충전액 $8 기준), 매출·비용·순수익 보고. 재무팀 만들기 전까지 비서가 맡는다.
- **로그인 없음:** 사장님만 쓰므로 비밀번호(`APP_PASSCODE`) 하나로 비용이 들거나 데이터를 바꾸는 API를 막는다.
- **DB:** 기획서의 PostgreSQL/Redis 대신 **Firebase Firestore 무료** (기존 focus-app 프로젝트 공유, `mpc_` 접두사). 고정비 0원.
- **기술:** Next.js(JavaScript) + Vercel Hobby. C#은 쓰지 않기로 함(속도 우선).
- **투자운영사업부 구조 (사장님 정의):** "학습시킨 직원 한 명당, 매매 프로그램 하나". 매매 방법 1개 = 직원 1명 = 전략 1개 → 직원끼리 성과 비교.
  직원마다 사진·URL·글로 학습, 실행 버튼(자동 스케줄 + 수동 실행 + 수동 매매), 현황(종목·금액·수익률), [+ 직원 추가].
- **매매 프로그램은 사장님 노트북에서 돈다** (Vercel·AWS 아님). 바이낸스 현물. 기존 파이썬 봇(선물·레버리지·물타기)은 쓰지 않고 새로 만듦.
- **폴링 금지:** Vercel·DB 무료 한도 때문에 30초마다 묻는 방식 금지 → Firestore 리스너 + 직원별 알람.
- 비서에게도 역할·지침(시스템 프롬프트) 편집창.

### 비서
- 됨: 비서 채팅, 역할·지침 편집.
- 아직: 2단계 API 크레딧·토큰 비용 보고($8 − 누적 비용) → 3단계 매출·비용 장부 → 4단계 구글 캘린더(iCal 주소 `GOOGLE_CALENDAR_ICS_URL` 방식 예정) → 5단계 데이터를 아는 비서 채팅 → 6단계 아침 텔레그램 브리핑.

### 마케팅사업부
- 부서 카드만 있음 ("준비 중", 직원 없음, `lib/departments.js`).

### 투자운영사업부 (거의 완성, 모의매매 단계)
- 직원 탭: **학습**(사진·URL·글 → Haiku가 한 번만 요약 저장, 원본 사진은 저장 안 함) → **전략**(Sonnet이 규칙표 JSON 작성, 버전 v1·v2…, 사장님 승인) → **프로그램**(모드 정지/모의, 자동 실행, 스케줄, 지금 실행, 모의·실제 매수/매도) → **현황**(수익률·보유·내역) → **대화·지침**.
- **전략 = 규칙표(JSON)이지 코드가 아니다.** 노트북 프로그램(고정 코드)이 규칙표를 해석해서 실행한다.
- **실행 가능 여부 확인:** 노트북 프로그램이 할 수 있는 일을 `lib/capabilities.js` = `worker/src/capabilities.js` 한 파일에 정의.
  전략 AI가 먼저 판단하고, 못 하는 부분은 바꿔 넣지 않고 '실행 불가' + 이유 + 대안. 규칙 검사는 엄격(모르는 항목이 있으면 실패)하고 사이트 승인 때·노트북 실행 때 둘 다 한다.
  화면의 "프로그램이 실제로 하는 일"은 AI 설명이 아니라 코드가 규칙에서 만든다.
- 지표: 가격, 가격 변화율, SMA, EMA, RSI(기존 GetRSI와 같은 값), 거래량 변화율, 볼린저 %B, MACD 히스토그램. 봉: 1m·5m·15m·1h·4h·1d.
- 스케줄: 전략 기본 / N분마다 / 매일 정해진 시각(한국 시간).
- **채팅 확인 카드:** 직원은 주문·설정·지금 실행 '제안' 카드만 만든다. 사장님이 [실행]을 눌러야 명령이 생긴다. 실전 카드는 확인창 + 서명. 30분 지나면 실행 불가.
- 노트북 프로그램(`worker/`): Node 22 + ccxt + Firebase 웹 SDK + pm2. 명령은 리스너로 받고, 자동 실행은 알람. 연결 신호만 5분마다. 실전은 테스트넷 기본, 실전 허용 기본 꺼짐(노트북 `.env`에서만 변경), 1회·일일 한도, 거래소 손절 주문.
- 사장님 노트북에서 실행·연결 확인 완료 ("오 잘된다").

## 5. 사장님 당부 (반드시 지킨다)

1. **실제 돈은 사장님이 버튼을 눌러야만 움직인다.** 자동 실행은 모의매매만. AI 직원은 주문하지 않고 확인 카드만 만든다.
2. **AI가 실행할 수 없는 걸 마음대로 바꿔서 실행하면 절대 안 된다.** 프로그램이 할 수 있는 일을 AI가 정확히 알고, 안 되면 안 된다고 알려 줘야 한다. (마케팅에서도 같은 원칙: 자동으로 게시·지원·발송하기 전에 사장님 확인)
3. **비용을 최소로:** 토큰은 가장 덜 들게, 교육은 확실하게. Vercel·Firestore 무료 한도 안에서. 주기적으로 읽는 코드·폴링 금지.
4. **키·비밀번호는 Vercel 환경변수와 노트북 `.env` 에만.** 코드·GitHub·Firestore·채팅에 넣지 않는다. 사장님도 채팅에 키를 보내지 않는다.
5. 사장님이 올렸던 예전 파이썬 봇 파일은 저장소에 올리지 않는다 (평문 바이낸스 시크릿·하드코딩 암호화 키가 들어 있었음 → 그 키는 폐기하라고 안내함).
6. 바이낸스 키는 출금 권한 끄기 + IP 제한.
7. Firestore 규칙은 사장님 요청으로 열어 둠. **다른 사람이 쓰기 전에 반드시 닫는다.**
8. 기능 브랜치 → 요약 보고 → 미리보기 → 컨펌 후 머지. 구현하라고 하기 전에는 구현하지 않는다.
9. 화면은 폰 우선, 부서는 사각형 카드.
10. 사장님이 "패스"라고 한 것은 건드리지 않는다 (예: 대화 직원에게 보유 목록 넘기기 → 패스).

## 6. 사장님이 원한 추가 기능 · 남은 일

### 투자운영사업부 (나중에 이 사업부 채팅에서)
- **과거 데이터를 제대로 읽는 전략**이 필요하다는 사장님 의견: "이만큼 오르면 사, 내리면 팔아"만으로는 사업부가 존재할 이유가 없다.
  봉 색깔(빨간봉/파란봉), 연속 개수, 봉 모양, 거래량이 몰리며 오르는 흐름, 차트 그림을 보고 오를지 판단해야 한다.
  제안한 대안 5개 (아직 선택 안 함):
  1. 캔들·거래량 어휘 확장 (봉 색깔, 연속 개수, 몸통·꼬리, 최고가 돌파, 거래량 배수·연속 증가, 거래량 동반 상승)
  2. 차트 패턴 라이브러리 (망치형, 장악형, 도지, 적삼병, 쌍바닥, 박스권 돌파, 눌림목)
  3. 과거 비슷한 구간 찾기 (지금 모양과 비슷한 과거 구간 뒤에 어떻게 됐는지 통계)
  4. AI가 매번 차트 판독 (1번 조건으로 먼저 거르고 걸린 경우만 AI 호출 — 비용·재현성 문제로 마지막)
  5. 백테스트 + AI 연구원 (지난 몇 달로 돌려 본 승률·수익률·최대 손실을 보고 승인, 버전별 개선)
  → 추천 순서: 1 → 5 → 2 또는 3, 4는 마지막.
- **매일 바뀌는 순위 스캔** (예: 어제 기준 상위 코인 10개 중 10% 떨어진 것): 지금은 실행 불가로 막힘. 스캔 기능 추가 제안함.
- **주식 연결:** 지금은 바이낸스 코인 전용. 증권사 REST API(한국투자증권 KIS 또는 키움 REST API, 둘 다 리눅스 가능)로 붙일 수 있음.
  장 시간, 주 단위 주문, 거래세, 호가·상하한가, 종목 코드 형식을 새로 처리해야 함. 모의매매는 시세 조회만 있으면 됨.
  **사장님 답변 대기:** 계좌 있는 증권사, 국내/미국.
- 노트북 할 일: pm2 등록·절전 끄기, `COMMAND_SIGNING_SECRET` 생성(Vercel + `.env`, Vercel은 Redeploy), 테스트넷 → 소액 실전.
  `main` 에 worker 변경이 머지되면 노트북에서 `git pull` 후 `pm2 restart all`.

1. **인스타그램·쓰레드 자동 운영 범위:** 글·이미지 기획만 / 초안 작성 / 예약 게시까지 / 댓글 응대까지?
   공식 API 사용 조건(계정 종류 — 비즈니스·크리에이터 계정 필요 여부, 앱 심사, 토큰 갱신)은 **최신 문서를 검색해서 확인한 뒤** 말한다.
2. **게시는 반자동:** 기본은 사장님이 카드에서 [승인]을 눌러야 게시 (5장 1·2번 원칙과 같음).
3. **계정 주제·말투·타깃:** 무엇을 알리는 계정인지, 학습 자료(투자부처럼 사진·URL·글)로 가르칠지.
4. **재택 수익모델 탐색:** 기획서 F1(알바몬 등 공고 수집·필터·지원서 초안). AI는 찾기·정리만, 지원은 사장님이 직접. 플랫폼 약관상 수집 가능 범위 확인 필요.
5. **어디서 돌릴지:** 사이트(Vercel, 크론 하루 1번 제한)로 충분한지, 노트북 프로그램에 붙일지. 폴링 금지 원칙 유지.
